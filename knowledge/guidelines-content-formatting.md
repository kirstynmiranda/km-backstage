# Vinted product writing formatting guidelines

This guide is the single source of truth for formatting content when building products at Vinted. It’s simple enough for anyone to use, whether you’re a designer, engineer, or a product manager.

## Formatting 

Formatting helps create a clear visual hierarchy. But when it’s used too often, it creates noise without being helpful. When in doubt, do without. 

#### Bolding in emails 

* **Create visual hierarchy \-** Use bold for headings, subheadings, and field labels to help members scan for the information they need 

* **In emails and message threads \-** Bold member names and item titles to provide context 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Hello, **lalaura1089,**   Your shipping label is attached to this message.   | **Hello, lalaura1089,**  Your **shipping label** is attached to this message.  |

* **Don’t bold punctuation \-** If a bold sentence ends in a full stop or colon, don’t bold the punctuation 


#### Italics

Avoid italics in Vinted. 

### Ampersands (&) 

* **Don’t use ampersands in UI copy** \- They are visually distracting, hard for screen readers to process, and they’re not localisation-friendly. 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Get your prepaid shipping label and send the order Pack and send  | Get your prepaid shipping label & send the order Pack & send |

* **Use ampersands for category names \-** We only use ampersands for **category names** (For example, “Hobbies & collectables”)

### Headings

Headings help members navigate Vinted by summarising the content of each section. Keep them short, clear, and scannable. 

* **Sentence case \-** Capitalise only the first word, proper nouns, and product names

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Item listed  | Item Listed  |

* **No full stops \-** Never use full stops for headers. You can use questions as titles in confirmation modals when a member needs to make a decision. 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Trust in your tech Still interested?  Resolve this issue?  | Trust in your tech.  Still interested. Resolve this issue  |

* **Be specific and informative \-** Use simple and specific language so members know what to expect

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Returning order to sender  | There was an issue with your order |

### Use lists and bullet points to improve scannability

Use lists to break up large blocks of information and to improve scannability in smaller screens ([Be device-agnostic](#be-device-agnostic)). 

#### Bullet points 

Use standard bullets (•) for short fragments or simple steps. 

* **Keep it short \-** If it’s longer than two sentences, it probably shouldn’t be a bullet   
    
* **Full stops \-** If a bullet point is a single sentence, don’t use a full stop. If it’s two sentences, both sentences should include a full stop. 

* **Use sentence case \-** Capitalise the first word of each bullet point 

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| List 5 items in a 30-day period  | list 5 items in a 30-day period  |

#### Numbered lists 

Used numbered lists when the order of items matters, like step-by-step instructions. 

* **Keep it short \-** If it’s longer than two sentences, consider breaking it up into additional steps

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| To get your shipping label:   1\. Go to the message thread with the buyer 2\. Select “Generate shipping label”  3\. Check your email for final instructions  | Here’s what you need to do:  1\. Go to the message thread between you and the buyer to generate the shipping label.  2\. Follow the steps on Vinted, and then the final steps in the email that arrives after the label is created.  |

* **Full stops \-** If a list item is a single sentence, don’t use a full stop. If it’s two sentences, both sentences should include a full stop. 

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| Here’s what you need to do:  1\. Go to the message thread between you and the buyer to generate the shipping label  2\. Follow the steps on Vinted, and then the final steps in the email that arrives after the label is created  | Here’s what you need to do:  1\. Go to the message thread between you and the buyer to generate the shipping label.  2\. Follow the steps on Vinted, and then the final steps in the email that arrives after the label is created.  |

#### Icon lists 

Use icons with headings when each point needs more explanation 

* **Treat headings like titles \-** Use sentence case and no punctuation   
    
* **Use standard punctuation for body text \-** Use standard punctuation and full stops, just like you would a regular paragraph 

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
|  |  |

### Numbers, currency, and dates

#### Numbers 

* Use numerals rather than spelling them out 

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| List 5 items  1 day ago  | List five items  One day ago  |

* **Separate character limits with a forward slash** 

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| 0/400 | 0 out of 400  |

#### Prices

* When writing prices, write the currency sign followed by a single space followed by the number written out. (For example, € 5000.50) 

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| € 5000 | €5000 5000 € |

#### Measurement units 

* Write the number followed by a space and the abbreviation of each unit ([Metric system abbreviations](#heading=h.hv0jgxxwnsxf))

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| 38 cm  500 g | 38 centimeters 500g |

#### Dates and time 

* **Long form \-** If there’s enough space, write out the day, followed by the abbreviated month followed by the year followed by the time ([Month abbreviations](#bookmark=id.67xzm7ysbi4d)).  All of these are separated by a single space. If the day of the month is less than 10, include a 0 beforehand.   
    
* **Short form \-** When space is limited, separate days, months, and years with a forward slash (dd/mm/yyyy) 


| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| 14 Jan 2026  05 Feb 2025  13/03/2026  | January 14, 2026  5 Feb 2025  2026/03/13  |

* **Time format \-** Time should always be written in 24-hour format. The hour and the minute are separated by a colon.

* **Remove ambiguity \-** For specific deadlines and time sensitive events, include both date and time, separated by a space 

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| 14 Jan 2026 20:04  13/03/2026 20:04  | 14 Jan 2026 at 8:04 PM  13/03/2026 8:04 PM  |


* **Time zones \-** When needed, add the time zone after the time, written out in caps and separated by a space (CEST, GMT, EST) 

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| 14 Jan 2026 20:04 CEST  | 14 Jan 2026 20:04  (Central European Summer Time)  14 Jan 2026 20:04  (UTC+2)  |

* **Date ranges \-** For recent events where the year is obvious, write each date in long form without the year, separated by a hyphen 

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| 05 Mar \- 12 Mar  | Mar 05 \- Mar 12  Mar 05-12  |

* **Use conversational time language when something isn’t time sensitive \-** Use conversational, approximate time references like “Just now” “less than one minute” and “5 days ago” 

| *✅ We would say* |  *❌ We wouldn’t say* |
| :---- | :---- |
| Just now  Less than one minute  5 days ago  | 32 seconds  57 seconds  5 days and 3 hours ago  |

| Month abbreviations used at Vinted  |
| :---- |
|  Jan  Feb  Mar Apr  May  Jun  Jul Aug  Sep  Oct  Nov  Dec  |

* **Writing decades:**   
  * Don’t write out the entire year   
  * Use short form when referring to decades   
  * Avoid apostrophes 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| 60s, 70s  | 60’s, 70’s  1960s, 1970s  |

| Metric system abbreviations   |  |
| :---- | :---- |
| Area  Distance  Length  Storage size  Volume  Weight | m² km m, cm,  KB, GB, TB  L, mL  g, kg  |
 

### Punctuation 

#### Colons (:)

* When writing times, use colons to separate hours and minutes (hh:mm) 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| 10:00 | 10.00  |

* Never put end punctuation on a form label or title 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
|  **Price**   €150.00   |  Price: €150.00  |

* Use colons to introduce list items or numbered items 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
|  How to earn this badge:   |  How to earn this badge  |

* #### Never use semi-colons (;) 

#### Commas

* Use commas sparingly in sentences and always read sentences aloud to make sure they sound conversational   
    
* Use oxford commas in sentences and when listing items 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Don’t worry, this transaction will be removed.  Don’t share personal data, click on external links, or scan QR codes.  | Don’t worry. This transaction will be removed.  Don’t share personal data, click on external links or scan QR codes.  |

* Don’t use commas to separate bulleted or numbered items 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| List 5 items in a 30-day period You’ll keep the badge even if you sell an item  | List 5 items in a 30-day period, You’ll keep the badge even if you sell an item  |

* When sentences begin with “Sorry” or “Don’t worry,” use a comma to deliver the rest of the message 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Don’t worry, this transaction will be removed.  Sorry, but the shipping provider wasn’t able to deliver the parcel | Don’t worry. This transaction will be removed.  Sorry but the shipping provider wasn’t able to deliver the parcel |

* When buttons begin with “OK,” “Yes,” or “No” followed by an action, we use a comma to separate the two words 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| OK, close  No, go back  | Ok and close  No…go back  |

* Only use ellipses for loading states

### Hyphens (‐), en-dashes (–), and em-dashes (—) 

#### Hyphens 

* Use hyphens as modifiers (30-day period) 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| 30-day period  | 30 day period  |


#### En-dashes 

* Use en-dashes for ranges (2–5 days) 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
|  2-5 days  |  2–5 days  |


#### Em-dashes 

In general, avoid. They are sometimes used in email or legal text to break up long sentences. 

#### Exclamation marks (\!) 

* Use exclamation marks in notifications when sharing updates or exciting news  
* ~~Use exclamation marks to convey a sense of urgency~~   
* Never use more than one exclamation mark in a sentence 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| In demand\! 3 buyers recently sent orders  \[member name\] left you feedback\!  Your parcel is on its way to the buyer\!  | In demand. 3 buyers recently sent orders.  \[member name\] left you feedback.  Your parcel is on its way to the buyer\!\!  |

### Full stops (.) 

* Avoid full stops on bulleted and numbered lists, unless they’re two sentences 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| List 5 items in a 30-day period Each day, we’ll review your previous 30 days of activity and update your status. If you meet the criteria, buyers will see the badge on your profile and listings.  | List 5 items in a 30-day period Each day, we’ll review your previous 30 days of activity and update your status. If you meet the criteria, buyers will see the badge on your profile and listings  |

* Avoid full stops on headers and push notifications, unless they are two sentences 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Speedy Shipping badge (header)  Tap “Everything is OK” to complete your order Keep what you love. List the rest before March for a fresh start.  | Speedy Shipping badge.  Tap “Everything is OK” to complete your order Keep what you love. List the rest before March for a fresh start  |

### Question marks (?) 

* Use question marks in modals where members have to make a decision. This helps them pause and consider whether they’re making the right choice. 

* **Avoid question marks when no decision is required \-** For example, if we are checking whether a parcel got lost, this does not require a decision from a member 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Delete carrier?  | Delete carrier  |

* ~~Use question marks in placeholders when necessary to keep text conversational~~


| ~~*✅ We would say*~~ |  ~~*❌We wouldn’t say*~~ |
| :---- | :---- |
| ~~How was your experience with this member?~~  | ~~Tell us about your experience with this member~~  |

* Use question marks when asking members for feedback 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| What do you think of our upload process?  | Tell us what you think about our upload process |

#### Quotation marks (“) 

Use double quotation marks when referring to a category, UI element, or a member-generated item name. Avoid single quotation marks. 

* Don’t use double quotation marks (“) when referring to a category, such as in placeholder text 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Search in Designer shoes  | Search designer shoes  Search in “Designer shoes”  |

* Use double quotation marks (“) when referring to a UI element, such as a button 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Select “Everything is OK” to complete your order  | Indicate everything is OK to complete your order  |

* Use double quotation marks (“) when referring to a member-generated item name in a notification or an email 

| *✅ We would say* |  *❌We wouldn’t say* |
| :---- | :---- |
| Leave feedback for Oversize Oysho jacket  | Leave feedback for “Oversize Oysho jacket” |
